🚀 Oracle VM + OmniRoute + Claude Setup

Complete step-by-step guide to set up your own AI gateway on Oracle Cloud's Always Free tier

Build a reusable Ubuntu AI gateway in under 30 minutes!

📊 What You'll Build

Your laptop / phone
        │
        │ SSH
        ▼
Oracle Cloud Ubuntu VM
   ├── Docker
   ├── OmniRoute :20128 (localhost only)
   └── Claude Code CLI
           │
           ▼
      Connected AI providers
      (Claude, Gemini, etc.)
How it works: Claude Code sends requests to OmniRoute at http://localhost:20128 on the VM. OmniRoute then routes the request to the provider/model configured in its dashboard.

✨ What's Included

  • ✅ Oracle Cloud Always Free VM (2 OCPUs, 12 GB RAM)
  • ✅ Docker + OmniRoute gateway
  • ✅ Claude Code CLI
  • ✅ Secure SSH access from any device
  • ✅ Multiple AI provider support
⚠️ Before You Start
  • An Oracle Cloud account with Always Free access
  • A laptop (Windows/macOS/Linux)
  • Basic command line knowledge
  • At least one AI provider API key (Claude, Gemini, etc.)
1

Create Oracle Cloud VM

Set up your Always Free Oracle Cloud VM with Ubuntu 24.04 LTS.

1.1 Navigate to Instances

  1. Open Oracle Cloud Console
  2. Main menu → Compute → Instances
  3. Click Create instance

1.2 Configure Instance Settings

Setting Recommended Value
Name Shadow-selfhost (or any name)
Image Ubuntu 24.04 LTS
Shape VM.Standard.A1.Flex (Arm64)
OCPUs / RAM Up to 2 OCPUs / 12 GB RAM
Public IPv4 ✅ Assign a public IPv4 address

1.3 SSH Key Setup

🔑 Important: During instance creation, download your SSH private key (.key file) and store it securely. Never share this key!

1.4 Network Security

Allow SSH access only:

Ingress rule:
Source CIDR: 0.0.0.0/0 (or your specific IP for better security)
Protocol: TCP
Destination port: 22
Note: Do NOT expose port 20128 publicly. We'll access OmniRoute through SSH tunneling.
2

Connect via SSH

Windows PowerShell

ssh -i "C:\Users\YOURNAME\Downloads\YOURKEY.key" ubuntu@YOUR_VM_PUBLIC_IP

macOS / Linux Terminal

ssh -i ~/Downloads/YOURKEY.key ubuntu@YOUR_VM_PUBLIC_IP

When prompted the first time, type yes to confirm the host key.

✅ Success: You should see a prompt like: ubuntu@YOUR-VM-NAME:~$

🔧 Key not found?

# Windows PowerShell
Test-Path "C:\Users\YOURNAME\Downloads\YOURKEY.key"

# macOS / Linux
ls -la ~/Downloads/*.key
3

Update Ubuntu & Verify Docker

Update System

sudo apt update
sudo apt upgrade -y

Check Docker

docker --version

Install Docker (if needed)

curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
⚠️ Important: After adding user to docker group, log out and reconnect for changes to take effect!

Verify Docker Access

docker ps
4

Install OmniRoute with Docker

This command installs OmniRoute bound to localhost for security.

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest

Verify Installation

docker ps
docker logs --tail 50 omniroute
✅ Success: You should see a container named omniroute with status Up.
5

Access OmniRoute Dashboard

Create an SSH tunnel to access the dashboard securely from your laptop.

Create SSH Tunnel (Windows)

ssh -i "C:\Users\YOURNAME\Downloads\YOURKEY.key" -L 20128:127.0.0.1:20128 ubuntu@YOUR_VM_PUBLIC_IP

Create SSH Tunnel (macOS/Linux)

ssh -i ~/Downloads/YOURKEY.key -L 20128:127.0.0.1:20128 ubuntu@YOUR_VM_PUBLIC_IP
📝 Keep this terminal window open! The tunnel needs to stay active while you use the dashboard.

Open Dashboard in Browser

http://127.0.0.1:20128
✅ You're in! The OmniRoute dashboard should now load in your browser.
6

Configure AI Providers

Add your AI providers to OmniRoute so it can route requests.

  1. Open the OmniRoute dashboard at http://127.0.0.1:20128
  2. Navigate to Providers
  3. Click Add Provider
  4. Select your provider (Claude, Gemini, etc.)
  5. Complete the OAuth or API key authentication
  6. Verify the provider appears in the model catalog

Create API Endpoint Key

  1. Go to Endpoints in the dashboard
  2. Create a new API key
  3. Copy and save this key securely
🔐 Security Note: The provider credential authorizes OmniRoute to call the AI provider. The endpoint key authorizes your clients to call OmniRoute. These are separate!
7

Verify Models

Check which models are available through your OmniRoute installation.

curl -s http://localhost:20128/v1/models \
  -H "Authorization: Bearer YOUR_OMNIROUTE_KEY"
💡 Important: Use the exact model IDs returned by this command. Don't guess model names!
8

Install Claude Code CLI

curl -fsSL https://claude.ai/install.sh | bash

Add to PATH

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

Verify Installation

claude --version
9

Connect Claude Code to OmniRoute

Configure environment variables to connect Claude Code to your OmniRoute gateway.

export CLAUDE_CONFIG_DIR="$HOME/.claude-omniroute"
export ANTHROPIC_BASE_URL="http://localhost:20128"
export ANTHROPIC_AUTH_TOKEN="YOUR_OMNIROUTE_KEY"
export ANTHROPIC_API_KEY=""
export ANTHROPIC_MODEL="YOUR_EXACT_MODEL_ID"
📌 Note: Replace YOUR_OMNIROUTE_KEY with the endpoint key from Step 6, and YOUR_EXACT_MODEL_ID with a model ID from Step 7.

Test the Connection

claude "Reply with one short sentence confirming the connection."
🎉 Success! If you get a response, Claude Code is now connected to OmniRoute!
10

Make Configuration Permanent

Add the environment variables to your ~/.bashrc so they persist across sessions.

nano ~/.bashrc

Add these lines at the end (with your real values):

export CLAUDE_CONFIG_DIR="$HOME/.claude-omniroute"
export ANTHROPIC_BASE_URL="http://localhost:20128"
export ANTHROPIC_AUTH_TOKEN="YOUR_OMNIROUTE_KEY"
export ANTHROPIC_API_KEY=""
export ANTHROPIC_MODEL="YOUR_EXACT_MODEL_ID"

Save and reload:

source ~/.bashrc
✅ Done! Now you can just type claude to start a session anytime.

🔄 Switching Between Models

To use a different model, simply change the ANTHROPIC_MODEL environment variable:

# Switch to Claude Sonnet
export ANTHROPIC_MODEL="kr/claude-sonnet-4.5"
claude

# Switch to O-Max
export ANTHROPIC_MODEL="O-Max"
claude
💡 Tip: Always use exact model IDs from /v1/models output.

🔧 Troubleshooting

Claude command not found

which claude
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

Claude doesn't use OmniRoute

echo $ANTHROPIC_BASE_URL
echo $ANTHROPIC_MODEL
echo $CLAUDE_CONFIG_DIR

Verify ANTHROPIC_BASE_URL is http://localhost:20128 and the model ID matches one from /v1/models.

Dashboard won't open

docker ps
curl -I http://localhost:20128

If curl works on the VM, recreate the SSH tunnel and keep that window open.

OmniRoute not running

docker ps -a
docker start omniroute
docker logs --tail 100 omniroute

Model list is empty

  • Confirm at least one provider is connected in the OmniRoute dashboard
  • Check that provider authentication is valid and not expired
  • Verify the model appears in /v1/models
  • Use the exact model ID, not a display name
  • Check OmniRoute logs for errors

📱 Access from Other Devices

From Another Laptop

Just create the same SSH tunnel from that device:

ssh -i "PATH_TO_YOUR_KEY" -L 20128:127.0.0.1:20128 ubuntu@YOUR_VM_PUBLIC_IP

From iPhone

  1. Install an SSH client like Termius
  2. Import your private SSH key
  3. Create a new host:
    • Host/IP: YOUR_VM_PUBLIC_IP
    • Port: 22
    • Username: ubuntu
    • Authentication: Your imported key
  4. For dashboard access, enable port forwarding in the SSH client settings

🔒 Security Checklist

  • ✅ Never share your SSH private key
  • ✅ Never share your OmniRoute API key
  • ✅ Never share provider API keys
  • ✅ Keep OmniRoute bound to 127.0.0.1 (localhost)
  • ✅ Do NOT open port 20128 to 0.0.0.0/0
  • ✅ Use SSH keys, not passwords
  • ✅ Set up Oracle budget/cost alerts
  • ✅ Back up important OmniRoute configuration
  • ✅ Rotate keys immediately if exposed
⚠️ If a key has been exposed: Revoke it immediately and create a replacement!

# 1) Update & Docker

export CLAUDE_CONFIG_DIR="$HOME/.claude-omniroute"
